# Guide de l'utilisateur

**ontoÉthique** (http://127.0.0.1:7280) évalue la **symbiose** entre les actants humains, les agents numériques (IA) et l'environnement documentaire d'une **activité située** : un cours, une rédaction assistée, une curation collaborative… Il applique le protocole de mesure des fluctuations du métamodèle onto-éthique :

- chaque **existence informationnelle** est décrite par quatre dimensions : matérielle (parties extensives), conceptuelle (essence), sociale (actant), temporelle (rapport) ;
- à chaque **pulsation** de l'activité, une existence exprime quatre **pouvoirs** : discerner, raisonner, résonner, agir ;
- chaque pouvoir reçoit un score **de -100 (diminution, tristesse) à +100 (augmentation, joie)**, 0 marquant l'indifférence, rattaché à sa séquence de sémiose (par exemple *physique → crible → actant → concept* pour discerner, *concept → actant → concept* pour raisonner, *concept → concept* pour résonner, *concept → actant → crible → physique* pour agir).

## 1. Préparer les traces

1. Dans Zotero (de préférence une **bibliothèque de groupe**, pour que chaque annotation garde son auteur), créer une collection contenant les traces de l'activité : comptes rendus, journaux de bord, captures, transcriptions d'échanges avec une IA, observations.
2. Les participants annotent ces traces dans le lecteur de Zotero : commentaires, notes, surlignages.
3. **Auto-évaluation** (facultative) : un participant ajoute à une annotation un marqueur comme `discerner+40`, `raisonner-30`, `résonner:60` ou `agir=-10`. L'annotation devient une pulsation de ce participant, **validée d'office** (souveraineté de l'expertise humaine).

## 2. Lancer une modélisation

1. **⚙ Paramètres** : renseigner Albert, Zotero et Omeka S, puis **Enregistrer et tester les connexions**.
2. Onglet **Activité** : titre et description de l'activité (tâche, participants, agents numériques, environnement, période), collection Zotero, réglages de lecture.
3. **Enregistrer et modéliser** : le journal s'affiche dans l'onglet **Exécution** ; à la fin, l'évaluation s'ouvre dans l'onglet **Diagrammes**.

Le traitement identifie les existences, évalue les pulsations de chaque trace, mesure les fluctuations et rédige une synthèse. Les **agents numériques n'ont pas accès au pouvoir de résonance** : leur score de Résonner est fixé par la règle de la barrière numérique (0 par défaut, réglable dans *Règles et seuils*).

**Sans collection ni modèle de langage** : **Nouvelle évaluation manuelle** crée une évaluation vide (existences et pulsations à saisir) ; **Charger l'exemple de l'article** reprend les scénarios A (rédaction manuelle) et B (rédaction assistée par une IA connexionniste).

## 3. Créer les items dans Omeka S

L'onglet **Formulaires Omeka S** suit le processus de modélisation : Physiques, Cribles, Personnes, Agents, Actants, Concepts, Pouvoirs existentiels, Pulsations existentielles, Raison trajective. Chaque formulaire vient du modèle de ressource : les listes sont celles des vocabulaires personnalisés, la classe et la collection d'items sont appliquées d'office.

- **Pouvoir existentiel** : choisir le type (la séquence attendue s'affiche), l'intensité (-100 : diminution extrême, 0 : pas de changement, 100 : augmentation extrême) et les maillons. Pour raisonner et résonner, saisir deux concepts avec **+ Ajouter une valeur** : le premier est la source, le second la destination.
- **Pulsation existentielle** : y ajouter ses pouvoirs, et la relier aux autres pulsations (flux) avec leur temporalité : avant, pendant, après, ordre successif.
- **Raison trajective** : y ajouter les pulsations, avec leur ordre.

Un item de même titre et de même modèle n'est pas recréé : le lien vers l'item existant s'affiche.

## 4. EcoNetwork : modéliser pas à pas

http://127.0.0.1:7280/econetwork (lien **EcoNetwork** dans l'en-tête) suit la modélisation étape par étape ; la colonne de gauche permet de revenir à une étape.

1. **1.1 Créer ou choisir un écosystème de connaissances** (un média peut être joint à la création).
2. **1.2 Réseau de l'écosystème** : l'écosystème au centre, ses éléments et les ressources qui leur sont liées. Glisser un nœud pour le déplacer, molette pour zoomer, **Recentrer** pour tout voir. Un clic sur un nœud ouvre son menu circulaire (icônes ; le libellé s'affiche au survol) :
   - **lier** : choisir dans le second anneau le type du nœud (les types possibles dépendent des propriétés du modèle du nœud), puis saisir un titre. Les items existants dont le titre contient la saisie sont proposés avec leur type (« déjà lié » s'ils le sont) : en choisir un pour le lier, sinon un nouveau nœud est créé, avec au besoin un **média** : **Fichier** (déposé dans Omeka S) ou **Adresse** (une adresse publique qu'Omeka S télécharge), et un titre facultatif. Le nœud lié est aussi rattaché à l'écosystème ;
   - **dupliquer** : même nœud, titre incrémenté ;
   - **détails** : onglet **Omeka S**, la page d'administration de l'item (se connecter une fois dans le cadre : la session est ensuite gardée, et l'on revient sur l'item) ; onglet **Fiche**, toutes les valeurs du nœud (un item lié présent dans le réseau ouvre sa propre fiche) ; **Nouvel onglet ↗** ;
   - **supprimer** : la fenêtre montre les nœuds parents (dont l'écosystème de rattachement) et les enfants impactés ; un rattachement à un autre écosystème bloque la suppression. **Retirer du réseau** garde l'item dans Omeka S ; **Supprimer dans Omeka S** n'est possible que si aucun autre nœud ne l'utilise (le **délier** d'abord) ;
   - **modifier** : le formulaire du type de nœud, pré-rempli.

## 5. EcoSpace : l'écosystème en trois dimensions

http://127.0.0.1:7280/ecospace (lien **EcoSpace** dans l'en-tête) représente l'écosystème dans un espace 3D.

1. **1.1 Créer ou choisir un écosystème** : un nouvel écosystème reçoit sa **grille hexagonale** ; pour un écosystème existant, **Créer la grille** à l'étape suivante.
   - **Nouvel écosystème depuis un texte** : décrire l'écosystème en six rubriques, ouvertes l'une après l'autre (**Étape suivante →**) : écosystème, actants et personnes, physiques, concepts, pouvoirs, pulsations. Chaque rubrique propose des **phrases modèles** (un clic les insère ; les parties entre {{ }} sont à compléter, **Tab** passe à la suivante). En écrivant, la liste des **titres existants** dans Omeka S et des noms déjà cités entre « » s'affiche : ↑ ↓ pour choisir, **Entrée** ou **Tab** pour insérer. **Suggérer la suite** demande à Albert une à trois phrases pour la rubrique, à **ajouter** ou **ignorer**. Le brouillon est gardé dans ce navigateur. **Analyser la description** fait modéliser le texte par un agent (une à trois minutes) ; la **modélisation proposée** s'affiche en tableaux à corriger : décocher ce qu'il ne faut pas créer, modifier titres, contenants, dates (AAAA, AAAA-MM ou AAAA-MM-JJ), lieux, type, intensité et maillons des pouvoirs (éléments d'un maillon séparés par « ; »), pouvoirs et flux des pulsations ; « existant » signale un item repris d'Omeka S. **Créer l'écosystème et son espace** crée tout dans Omeka S et dans l'espace : l'origine de la grille est le lieu de l'écosystème, chaque actant et physique est placé à son lieu et reçoit sa position datée, les pulsations aussi ; ce qui ne peut pas être créé est signalé à la fin, puis l'espace s'ouvre. Les saisies sont **conservées dans l'item de l'écosystème** (propriété « jdc:pipeline », visible dans Omeka S) : le texte de chaque rubrique, les suites proposées par Albert (ajoutées ou ignorées), la modélisation de l'agent et la modélisation validée, chacune avec sa demande, sa réponse, le modèle et le coût.
2. **1.2 Espace de l'écosystème** : au-dessus de l'espace, quatre **rubriques** s'ouvrent ou se replient d'un clic sur leur titre (le choix est mémorisé dans ce navigateur) : **Aide**, **Vues et affichage** (vues, liste des éléments, légende, origine géographique ; les boutons **Éléments** et **Légende** sont grisés quand leur bloc est masqué), **Pulsations** (lancer ou arrêter l'**animation**, arrêtée à l'ouverture de la page, **vitesse**, échelle des couleurs, **suivre** une pulsation) et **Échelle temporelle** (hauteur, mode et streamgraph ; repliée, elle rappelle les dates affichées). Dans l'espace, la zone **sous la grille** a une couleur de fond propre (gris-bleu) qui la distingue du reste ; vu d'en dessous, c'est l'inverse. Glisser pour tourner, clic droit (ou Maj + glisser) pour déplacer, molette pour zoomer, double-clic pour s'approcher d'un hexagone ; **Vue d'ensemble**, **Vue de dessus**, **Vue de dessous**. Le survol d'un hexagone affiche ses coordonnées **cube** (q, r, s) et **géographiques** (longitude, latitude, altitude). Le bouton **Origine géographique** ouvre une carte : rechercher un lieu (adresse, ville, monument), utiliser **Ma position**, ou cliquer sur la carte et déplacer le repère ; le cercle montre l'emprise de la grille. **Enregistrer l'origine** place le centre de la grille sur ce lieu : les actants et les physiques gardent leur position géographique et changent d'hexagone si besoin (personnes et agents suivent leur actant). Quand des éléments sont loin les uns des autres, la grille passe à des **hexagones plus grands**, à la façon de l'index géographique H3 : chaque niveau est √7 (2,6) fois plus grand que le précédent et légèrement tourné (26 m, 70 m, 185 m… 24 km), et chaque hexagone se découpe exactement en 7 hexagones plus petits. Un grand hexagone qui contient des éléments affiche leur nombre (survoler pour le détail par type) et, quand on s'en approche (molette ou clic sur ce nombre), se découpe en ses 7 enfants, et ainsi de suite jusqu'aux hexagones de base où sont posés les éléments. Chaque actant, physique et personne a un **historique de ses positions** (fichier GeoJSON, un point par position, copié comme média de l'item dans Omeka S si celui-ci accepte le type de média « application/geo+json » et l'extension « geojson ») : les détails de l'élément donnent sa position géographique de référence et un lien vers cet historique. L'action **position** (menu circulaire et liste des éléments, pour un actant, un physique racine ou une pulsation) ouvre une carte : choisir le lieu (recherche d'une **adresse**, clic, repère à déplacer ou saisie des coordonnées) et la **date**, puis **Ajouter la position**. La position la plus récente est celle de l'élément, qui change d'hexagone en conséquence ; une date plus ancienne complète seulement l'historique. Le tableau de l'historique permet de **corriger** (lieu et date) ou de **supprimer** une position ; la trajectoire apparaît en pointillés sur la carte. Chaque position est aussi enregistrée dans la propriété **jdc:hasPosition** de l'item dans Omeka S, annotée selon le modèle « Position spatio-temporelle » (titre, adresse, coordonnées, date) ; les positions saisies directement dans Omeka S sont conservées. La **légende** des formes (et la description de la grille) est cachée par défaut pour gagner de la place ; le bouton **Légende** l'affiche ou la cache. Le bouton **Éléments** affiche ou masque, à droite de l'espace, la **liste des éléments par type** (actants, personnes, agents, pouvoirs, physiques, concepts, cribles ; enfants en retrait sous leur parent, repliés par défaut : ▸ les déplie, ▾ les replie ; le filtre cherche aussi dans les enfants repliés), avec un champ de filtre par titre. Pour chaque élément : la case l'**affiche** ou le **cache** (avec ce qu'il contient : physiques et concepts enfants, personnes et agents d'un actant, et les tubes qui y aboutissent) ; un clic sur son titre ou sur la loupe **zoome** dessus (sur son fullerène pour un actant) ; puis **détails**, **modifier**, **dupliquer** et **supprimer**, comme dans le menu circulaire. La case d'un type cache ou affiche tout le type ; **Tout afficher** rétablit tout. Les éléments cachés sont mémorisés par écosystème dans ce navigateur seulement. Les positions de l'espace sont aussi **copiées dans Omeka S**, comme média de l'écosystème (fichier `ecospace-<numéro>.json`), quelques secondes après chaque modification ; la ligne d'information indique l'état de cette copie. Il faut pour cela qu'Omeka S accepte les fichiers JSON (Administration > Paramètres > Sécurité : type `application/json`, extension `json`). Pendant une opération qui prend du temps (chargement, liens entre concepts, duplication…), une **fenêtre** indique ce qui se passe : les étapes terminées et celle en cours, avec leur durée. Un clic ouvre le menu circulaire ; **lier** n'y propose que ce qui est possible : sur un hexagone libre, les éléments qui peuvent y être placés ; sur un élément, les liens prévus par son modèle (resource template) — un actant : personne et agent ; un physique : physique enfant ; un concept : parent, enfant, détacher ; une personne ou un agent : rien. Le **streamgraph** sous l'échelle temporelle montre, au fil du temps (dans le mode de l'échelle : linéaire ou logarithmique), le **nombre d'éléments de chaque type** présents à chaque date : physiques depuis leur création (sans leurs enfants), actants et personnes selon leurs positions datées, agents avec leur actant, autres éléments depuis leur placement ; l'épaisseur d'un flux est ce nombre, la légende donne les effectifs actuels et le survol ceux de la date pointée. **Glisser sur le streamgraph** (brush) choisit les dates affichées ; les éléments qui ne sont présents à aucun moment de cette période sont masqués dans l'espace et dans la liste des éléments (qui indique combien), ainsi que les pouvoirs, cribles et pulsations dont tous les éléments le sont, et les nombres des grands hexagones ne comptent que les éléments affichés : l'échelle temporelle de l'espace couvre alors cette période (haut = début, surface = fin) et les actants et physiques qui ont des positions datées sont **déplacés sur la grille** à leur position à la fin de la période (sur l'hexagone libre le plus proche s'il est occupé), avec leurs personnes, agents, concepts et les tubes qui les relient ; **Toutes les dates** ou un clic hors de la sélection revient à toute l'étendue. Dans l'espace, chaque élément suivi trace son **chemin spatio-temporel** : un trait vertical tant qu'il reste au même endroit (la hauteur donne la date), un trait horizontal quand il se déplace ; une position lointaine est ramenée au bord de l'espace avec sa distance.
   - sur un hexagone libre, **lier** puis choisir le type d'élément : l'**Actant**, le **Physique** et le **Concept** ont leur forme ; **Personne** et **Agent** s'ajoutent depuis un actant ; les autres types suivront. Saisir un titre : un actant existant peut être choisi, sinon il est créé (média facultatif). L'actant apparaît sous la forme d'un **fullerène** (molécule C60) centré sur l'hexagone et d'une **sphère**, tous deux du même rayon que l'hexagone, dont le pôle nord touche le centre du fullerène, sous la grille ; **détails** donne les coordonnées de l'hexagone ;
   - **Personne** et **Agent** : ils ne s'ajoutent que **depuis un actant** (son menu **lier** propose Personne et Agent, à créer ou à choisir parmi les existants). Chacun est, comme l'actant, un **petit fullerène** avec une **sphère** sous la grille (bleus pour une personne, ocre pour un agent ; la sphère de l'actant devient alors translucide pour les laisser voir) centré sur une **sous-grille hexagonale** dessinée sur l'hexagone de l'actant (moitié au-dessus, moitié en dessous de la grille) : le centre reste à l'actant, les suivants se placent anneau par anneau. **Supprimer** propose de le détacher de l'actant (l'item reste dans Omeka S) ;
   - **Pouvoir** : un **cylindre** (tube translucide) qui relie les éléments de sa chaîne, dans l'ordre de son type, avec sa couleur : **Discerner** (bleu) physique → crible → actant → concept ; **Agir** (rouge) concept → actant → crible → physique ; **Raisonner** (violet) et **Résonner** (or) concept → concept. Les **concepts des pouvoirs vont dans la sphère de leur actant**, qui grandit pour les contenir ; un concept relié à plusieurs actants se place à l'**intersection** de leurs sphères. Le **crible** est un anneau traversé par le tube. Un pouvoir se crée depuis **n'importe lequel de ses éléments** : **lier** sur un physique, un crible, un actant ou un concept propose chaque type de pouvoir où cet élément peut figurer (un physique : Discerner, Agir ; un actant ou un crible : Discerner, Agir, et Raisonner, Résonner pour l'actant ; un concept : les quatre, avec « source » ou « destination » pour Raisonner et Résonner) ; l'élément est fixé à son maillon et un dialogue demande les autres maillons (« + » pour en relier plusieurs) et l'intensité (−100 à +100). **Cliquer sur le tube**, puis **lier → Connecter ici**, branche à cet endroit un nouvel élément (le maillon est au choix ; le tube reste découpé en hexagones invisibles, celui qui est visé s'entoure de blanc) : un tube enfant part de cet endroit. **Branche** crée un autre pouvoir du même type qui reprend la chaîne ;
   - **Pulsation existentielle** : un **éclair lumineux** qui part d'un **foyer ⚡** (petit octaèdre lumineux au-dessus de la **position spatio-temporelle** de la pulsation — à la date de la surface de l'échelle temporelle, comme les actants et physiques ; positions ajoutées par l'action **position** ou saisies dans Omeka S dans « jdc:hasPosition » avec leurs coordonnées et leur date — sinon au-dessus du premier élément, ou de la grille si cet élément est dessous ; une pulsation qui a des positions apparaît dans le streamgraph, a son chemin spatio-temporel et est masquée hors de la période choisie) et se propage d'élément en élément **par l'intérieur des tubes** de ses pouvoirs, **dans l'ordre** : les pouvoirs selon leur ordre successif (sinon leur ordre d'ajout), puis, pour chacun, les éléments de chaque maillon de sa séquence (un crible : son anneau ; l'actant hôte d'un pouvoir de raisonner ou de résonner est sauté, comme par le tube) ; chaque élément atteint s'éclaire, puis l'éclair repart du foyer après une courte pause. Sa **couleur** suit l'**échelle turbo** selon l'intensité du pouvoir parcouru, de −100 (bleu foncé) à +100 (rouge), vert vif à 0 (l'échelle est rappelée dans la barre d'outils) ; le foyer prend la couleur de l'intensité moyenne. Le curseur **Vitesse** règle la vitesse de propagation (0,5 à 20 hexagones par seconde, mémorisée dans le navigateur). Les détails donnent le **parcours de l'éclair**. Elle se crée **depuis un pouvoir** : cliquer sur un tube, **lier → Pulsation**, puis choisir une pulsation existante (le pouvoir y est ajouté) ou saisir le titre d'une nouvelle. Sur un foyer, **lier → Pouvoir** ajoute un autre pouvoir de l'espace ; **lier → Flux** la relie à une autre pulsation avec sa **temporalité** : ordre relatif de la cible (**Après** : la flèche va vers elle ; **Avant** : elle en vient ; **Pendant** : trait double sans flèche) et **ordre successif** (rang du flux). Le flux est un arc fléché d'un foyer à l'autre où circulent des particules, étiqueté par sa temporalité. La pulsation se sélectionne par son foyer. Le bouton **Pulsations** arrête ou relance l'animation ; La vitesse varie selon la distance : un saut court suit la vitesse choisie, un saut long va plus vite (au plus 4 secondes, même entre des éléments éloignés de plusieurs kilomètres), et l'éclair ralentit en partant et en arrivant ; de loin, l'éclair et sa tête grossissent pour rester visibles, et ils restent visibles à l'intérieur des sphères. Dans la rubrique **Pulsations**, choisir une pulsation puis **Suivre** : la caméra accompagne l'éclair d'élément en élément (on peut toujours tourner et zoomer) et la ligne d'information indique l'élément visé, son pouvoir et l'étape ; à chaque élément atteint, la pulsation **s'arrête quelques secondes** (curseur **Pause**, 0 pour ne pas s'arrêter) et la vue **zoome sur l'élément** (un concept, un physique précis, le fullerène d'un actant) avant de reprendre ; **⏸ Pause** fige la pulsation suivie (on peut alors tourner autour), **▶ Reprendre** la relance. **Parcours** déplie la liste des étapes de la pulsation (élément, type, pouvoir), l'étape en cours est surlignée et un clic sur une étape y amène l'éclair ; **Arrêter le suivi**, Échap ou un autre déplacement de vue (vue d'ensemble, zoom) l'arrêtent.
   - **Physique** : une **boîte** posée sur l'hexagone, qui s'élève selon le temps : la surface de la grille est *maintenant*, le haut de l'échelle la plus ancienne date de création des physiques. La boîte va de la date de dernière modification (en bas) à la date de création (en haut) : sa hauteur est sa durée. À la création, saisir la **date de création** (AAAA, AAAA-MM-JJ…) et l'**importance**. Sur un physique, **lier** ajoute un **physique enfant** : une boîte à l'intérieur de son parent. Les enfants sont empilés de haut en bas dans l'ordre alphabétique de leur titre, et la hauteur de chacun est proportionnelle à son importance face à celle des autres enfants. Si le physique a un **média image**, l'image est plaquée sur les faces de sa boîte. Le curseur **Échelle temporelle** étire ou resserre l'échelle (position et hauteur des boîtes) ; le mode **logarithmique** dilate les périodes récentes ;
   - **Concept** : une **bulle conceptuelle** couchée sous la grille, orientée est-ouest (cylindre terminé par deux demi-sphères). Sa taille et sa place sont **calculées**, on ne les règle pas à la main : une bulle sans enfant est juste assez longue pour son titre ; une bulle parent englobe ses enfants, rangés côte à côte par ordre alphabétique, son propre titre au-dessus d'eux. Les concepts de même niveau sont répartis de façon équilibrée (écarts égaux, centrés) ; les concepts sans parent forment une grille centrée sous l'espace. La hiérarchie vient d'Omeka S (*skos:narrower* / *skos:broader*) et se modifie par le menu du concept, **lier** : **Concept parent** (un concept qui l'englobera ; s'il avait déjà un parent, le nouveau s'intercale), **Concept enfant** (un concept qu'il englobera ; un concept existant quitte son ancien parent) ou **Détacher** (il redevient un concept sans parent). Chaque relation écrite est annotée par l'écosystème. Supprimer un concept de l'espace ne touche pas à ses relations dans Omeka S ;
   - un hexagone peut porter **un actant et un physique** (l'un sous la grille, l'autre au-dessus) : sur l'un, **lier** propose l'autre type ;
   - sur un élément placé : **dupliquer** (indiquer le nombre de copies ; chacune va sur l'hexagone libre le plus proche), **détails** (Omeka S, fiche et position), **supprimer** (retirer de l'espace, de l'écosystème, ou supprimer dans Omeka S ; un physique enfant peut être **détaché** de son parent), **modifier**. Pour atteindre un physique qui contient des enfants, cliquer dans sa marge, autour d'eux.

## 6. Lire et corriger l'évaluation

| Onglet | Contenu |
|---|---|
| **Existences** | une fiche par existence : genre, éléments des quatre dimensions, cribles, traces, complexité ontologique ; cliquer pour modifier, **Ajouter une existence** |
| **Matrice des affects** | une ligne par pulsation : scores colorés (rouge : diminution, vert : augmentation), origine (*agent*, *humain*, *autoevaluation*, *regle*) et ✔ si validé. Cliquer sur une ligne ouvre l'éditeur : score (curseur), état de la grille, maillons de la séquence de sémiose, justification, citation, valeurs tardiennes |
| **Diagrammes** | indice et équilibre de la symbiose, alertes, **spirales coniques de Pappus**, profils des pouvoirs, moyennes par genre, tableau des moyennes et des états |
| **Synthèse** | discours de l'ADA onto-éthique (les références `[p3]` ouvrent la pulsation) ; **Nouvelle synthèse** après corrections |
| **Rapport** | rapport de l'exécution (consommation, coût) et fichiers : modèle JSON, matrice CSV, Turtle, JSON-LD, spirales |
| **Évaluations** | toutes les évaluations (archive locale et Omeka S) : ouvrir, supprimer |

**Corriger et valider** : dans l'éditeur, une évaluation modifiée devient *humaine* ; la case **validé** (ou **Tout valider et enregistrer**) confirme une proposition de l'agent. Indiquer **votre nom** et le **motif** : chaque correction est tracée dans l'historique des **révisions**, exporté avec le modèle. Les indicateurs, les spirales et les fichiers sont recalculés à chaque enregistrement.

**Enregistrer dans Omeka S** (bandeau de l'évaluation) dépose la version corrigée dans l'item de configuration de l'évaluation (créé pour une évaluation manuelle).

## 7. Interpréter

- **Grille des affects** : Discerner (cécité cognitive / stase / clarté sémiotique), Raisonner (aliénation logique / routinisation / puissance critique), Résonner (impasse intuitive / barrière numérique / scientia intuitiva), Agir (misère symbolique / geste blanc / création autopoïétique).
- **Valeurs tardiennes** : utilité et beauté (Désir), vérité (Croyance) de ce qui est discerné ; une valeur-vérité effondrée signale l'**indignation**.
- **Symbiose** : l'indice (de -1 à 1) est la valence moyenne des existences ; l'équilibre (de 0 à 1) compare humains, agents et environnement. Un indice positif avec un faible équilibre signale un profit asymétrique.
- **Alertes** : notamment le risque de **misère symbolique** — un humain dont les pouvoirs de raisonner et de résonner diminuent tandis qu'un agent agit fortement.
- **Spirale de Pappus** : rayon = augmentations de Résonner, altitude = augmentations d'Agir, rotation = Discerner + Raisonner. Un **cône évasé** traduit des intuitions nombreuses, une **flèche** une production sans résonance, un **tube** une activité qui sédimente sans se dilater.

Les scores sont des **expressions situées et subjectives**, non des mesures physiques : la matrice est un support pour une **éthique de la discussion** entre participants, que la synthèse prolonge par des questions ouvertes.
